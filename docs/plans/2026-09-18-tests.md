# Plan: Unit tests for ExoPdf.Core

**Date:** 2026-09-18
**Branch:** feature/tests
**Related requirements:** docs/requirements.md — Merge operation

## Goal

Add a test project covering the public API of `ExoPdf.Core`, starting with
`PdfMerger`.

## Context

Core is now isolated with no UI dependencies, making it straightforward to test.
Tests create real (minimal) PDFs in temp directories using PDFsharp — no mocking
of file I/O. This matches the project's philosophy of testing against real
behaviour rather than fakes.

## Alternatives considered

| Option | Reason rejected |
|---|---|
| Mock the file system | Hides real I/O bugs; PDFsharp cannot be trivially abstracted |
| Use pre-built fixture PDF files | Brittle — files must be kept in sync; harder to control page count and bookmarks |
| Integration tests only (full CLI invocation) | Harder to isolate failures; overkill for Core logic |

## Chosen approach

**xUnit** test project (`ExoPdf.Tests`) with a `PdfFixture` helper that creates
minimal PDFs programmatically using PDFsharp. Tests run against a real temp
directory, cleaned up after each test.

No assertion library beyond xUnit's built-in `Assert` — keeps dependencies
minimal.

## Steps

### 1 — Create `ExoPdf.Tests` (xUnit, net8.0)

- Add to `ExoPdf.slnx`
- Add project reference to `ExoPdf.Core`
- Add `PDFsharp` package reference (to create test PDFs)

### 2 — Add `PdfFixture` helper

`Tests/PdfFixture.cs` — static helper with two methods:
- `CreatePdf(folder, fileName, pageCount)` → creates a minimal PDF with N blank pages
- `CreatePdfWithBookmarks(folder, fileName, pageCount, bookmarkTitles[])` → same but
  adds top-level bookmarks pointing to each page

### 3 — Write tests for `PdfMerger`

`Tests/PdfMergerTests.cs`:

| Test | Verifies |
|---|---|
| `Merge_SingleFile_ReturnsCorrectPageCount` | Result.TotalPages matches input |
| `Merge_MultipleFiles_CombinesPageCounts` | Total pages = sum of all inputs |
| `Merge_MultipleFiles_ReturnsCorrectFileCount` | Result.FilesMerged matches file count |
| `Merge_OutputSavedInSourceFolder` | Result.OutputFilePath is inside source folder |
| `Merge_EachFileGetsTopLevelBookmark` | Output has one top-level bookmark per file |
| `Merge_BookmarkTitlesMatchFileNamesWithoutExtension` | Bookmark titles strip `.pdf` |
| `Merge_FileWithBookmarks_PreservesAsChildren` | Source bookmarks appear as children |
| `Merge_FileWithoutBookmarks_NoChildren` | Files without bookmarks have no children |

### 4 — Verify all tests pass

```bash
dotnet test ExoPdf.Tests/ExoPdf.Tests.csproj
```

## Out of scope

- Testing `ExoPdf.Cli` commands (CLI integration tests are a separate task)
- Testing `ExoPdf.Desktop` ViewModels (no operations wired up yet)
- Edge cases for corrupt or encrypted PDFs
